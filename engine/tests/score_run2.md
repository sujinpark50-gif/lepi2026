# 5단계 검증 점수 (run 2, Opus vs Sonnet)

- 입력: `run2_opus.json`·`run2_sonnet.json`(각 13개)과 로그. 판정 결과: `run2_opus_judge.json`(10회), `run2_sonnet_judge.json`(9회), `run1_opus_judge_v2.json`(12회). 판정 API 31회.
- 루브릭이 run1 채점 뒤에 바뀌었다(감점 두 줄 추가). 그래서 run1도 같은 판으로 다시 채점했다. run1 평균은 21.2에서 20.8이 됐다. 무화과는 28점에서 26점으로, 쥐꼬리는 17점에서 18점으로 바뀌었다.
- 척도: 품질 % = (총점 − 10.4) / (18.1 − 10.4). 60% = 15.1, 70% = 15.8. 판정기 흔들림은 글 하나당 ±2점이다.
- 통과 기준: 지어낸 사실 0 + 규칙 위반 0 + 감성 ≤ 1/3 + 글 하나 최저선. 규칙에는 writer.md 맨 위 새 원칙도 들어간다(가치를 깎는 사실 금지, 매력 중심, 제철로 열기, 상품명 상식).
  - **새 최저선**: 총점 14 이상, 0점 항목 없음. 괄호 안은 옛 최저선(15 이상, 1점 이하 항목 없음)으로 본 결과다.
- NEED_MORE_INFO는 되묻는 게 맞고 질문도 좋을 때만 통과로 센다. 감성 비율은 끝맺음이 약속·인사일 때만 빼고 센다.

## 3. NEED_MORE_INFO 판정: 닉스고·잉어킹·선운사는 회귀다

- run1에서는 셋 다 READY였다(run1 닉스고 23점, 잉어킹 21점). run2는 닉스고·잉어킹을 두 모델 모두, 선운사를 Sonnet이 되물었다.
- **원인 (설계)**: `analyzer.md` 42행은 READY에 `seller_scene`을 요구하면서 "DEMO의 buyer_action은 seller_scene이 될 수 없다"고 한다. 구매담뿐인 DEMO는 재료가 많아도 막힌다. 닉스고에는 응원·귀여움·실제 말을 본뜬 외형·8천 원이, 잉어킹에는 analyzer가 뽑은 상식 "힘없지만 버티면 아주 센 캐릭터"와 덧붙임 글귀가 있었다. 사용자가 원한 잉어킹 상식 이야기는 writer까지 가지도 못했다.
- 선운사(Sonnet): "바람에 풍경처럼 흔들리면서 촤르르 소리"를 `product`로 분류했다. analyzer.md 12행의 seller_scene 예("걸어 두니 소리가 났다")와 같은 경우다. Opus는 seller_scene으로 분류해 17점 글을 냈다. **모델이 프롬프트를 따르지 못한 문제**다.
- 질문: Opus 잉어킹·Sonnet 닉스고·Sonnet 선운사의 "산 뒤 곁에 두고 어떻게 지냈나"는 구체적이지만 묻지 않아도 될 질문이다. Opus 닉스고의 "만들거나 고르면서 직접 하신 일"은 DEMO 사용자에게 맞지 않는 **나쁜 질문**이다. 아메리카노는 두 모델 모두 맞게 되물었다.

## 7. Opus와 Sonnet

- **판정: Sonnet 품질은 충분히 가깝다.** 같은 9개 메모 평균 20.0 대 19.9(판정기 오차 ±0.5 안), 새 최저선 통과 10 대 10. 원가는 54%(32.7원 대 60.1원), 시간은 75%.
- Sonnet이 약한 곳: 분류가 덜 정확하다(선운사). 재작성 뒤 어색한 문장이 더 남는다(밀짚, 딸기, 반려돌). 메모를 그대로 옮긴 글이 더 많다(단풍). 옛 최저선 미달이 2개다.
- 제안: 6절 1행(DEMO READY 조건)과 재작성 다듬기를 고친 뒤 Sonnet을 기본으로 둔다. 13개를 한 번 더 돌려 차이를 확인한다.
